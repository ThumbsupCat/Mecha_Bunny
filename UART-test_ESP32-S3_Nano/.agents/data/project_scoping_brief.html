Project Overview

A high-level summary of the Mechanized Bunny project, its main objectives, and core behavior.

Main Objective

Build an interactive robotic companion bunny that uses the NXP FRDM-MCXA153 for local sensory-motor control and emotional expressions, paired with an ESP32 co-processor to connect to a cloud conversational AI API (answering questions and detecting sentiment/mood).

Operating Environment

Indoor flat surfaces (e.g., classroom tables, lab benches, or smooth floors) with active Wi-Fi connectivity. The bunny must actively track and follow the user while responding.

Project Ambition Tiers

Proposed tiers to balance beginner learning constraints with ambitious student achievements.

Core Student Version Intermediate

A static desktop companion bunny focused on basic networking, serial communication, and simple UI rendering.

Features:
  • UART-based ESP32 commands
  • Wi-Fi connection to simple REST API
  • Text query input via Serial Console
  • OLED display showing text and mood tags

Suitable: Focuses purely on software protocols without robotics overhead.

Recommended Version Advanced

A mobile, responsive robot that tracks the user and physically wiggles its ears based on conversation sentiment.

Features:
  • Differential drive DC motors + driver
  • Ultrasonic sensors to follow user
  • PWM-driven servos for wiggling ears
  • ESP32 hosts smartphone web page input
  • Animated pixel-art expressions on OLED

Suitable: Balanced robotics demo combining control loops and web integrations.

Advanced Extension Advanced+

An autonomous, voice-activated companion using camera tracking and localized speech streaming.

Features:
  • MEMS microphone audio stream (I2S)
  • Speech-to-Text and TTS via Speaker (I2S)
  • ESP32-CAM or HuskyLens face tracking
  • Local TinyML wake word recognition
  • LiPo power with charger/gauge circuits

Suitable: Optional stretch goal for highly capable students.

Key Scoping Assumptions

Assumptions made to ensure feasibility within a summer school timeframe.

A-001: Web-assisted Conversation

Instead of direct audio processing on the MCXA153, the user types or speaks to a web app served by the ESP32. The ESP32 handles Web-to-API communication. (Reduces RAM requirements).

A-002: Structured JSON API

The cloud API returns a simple, small JSON object containing pre-processed reply text and discrete mood tags, bypassing stream parsing complexity.

A-003: Custom ESP32 Firmware

The ESP32 runs custom Arduino/ESP-IDF code to offload Wi-Fi/HTTPS logic, acting as an intelligent bridge to MCXA153 rather than relying on complex serial AT command sets.

Technical Risks & Risk Controls

Identified project risks and mitigation strategies for student developers.

Power MCU resets/brownouts due to shared power

DC motors and servo motors draw significant current spikes that can drop supply lines, resetting the MCXA153. Mitigate by using separate power regulators/batteries for logic and motors, with a shared common ground, and placing decoupling capacitors near the motor driver.

Voltage 5V and 3.3V Logic Level Incompatibilities

Many hobbyist sensors (HC-SR04) and motor drivers operate on 5V. Connecting their output pins directly to the FRDM-MCXA153 will damage the MCU. Mitigate by using 3.3V native components (like the RCWL-1601) or placing resistor dividers/level shifters on all signals entering the MCU.

Memory SRAM limits on MCXA153 (32 KB)

The MCXA153 has limited RAM. Parsing long sentences, holding audio buffers, or processing images locally is impossible. Mitigate by executing all NLP, voice-to-text, and image tracking on the ESP32 or in the cloud, passing only brief JSON text to the MCU.

Timing Blocked control loops during Wi-Fi querying

If the MCU blocks waiting for the UART response from the ESP32, the motor control loop will freeze, causing the bunny to crash. Mitigate by implementing non-blocking UART interrupts or ring buffers, and using a state machine for motor navigation.

Software Context & Developer Setup

SDK, IDE, and codebase recommendations for the development team.

Development Environment

IDE: MCUXpresso VS Code Edition or MCUXpresso IDE.
Language: C
SDK Components: fsl_lpuart (UART), fsl_i2c (OLED/Sensors), fsl_tpm/ftm (PWM servos and motor driver).

Starting Point Strategy

Start by executing the lpuart_interrupt SDK example to ensure reliable, non-blocking serial communication with the ESP32. Set up the pin routes in NXP's Pin Tool, prioritizing generic pin configurations before finalizing layout.
